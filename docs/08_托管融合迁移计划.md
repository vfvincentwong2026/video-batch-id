## 一、路线修正：从「合并代码」到「安装为受治理对等体」

v1 假设的迁移方式是**把 packages/* 代码并入 ai-native-dam**。ADR 0009 定了另一条路，更轻也更对：

> **An installed unit talks MCP in both directions: unit → DAM (check_usage_rights, record_usage, register_skill); DAM → unit (probe health, pull metrics, push version, revoke, rollback). A black-box container is not installable at L2+.**

**Video Batch ID 不是被拆散吞并，而是作为 L2 Hostable 单元被安装**：保留自己的 repo、运行时、SQLite 执行状态，通过 `dam.manifest.yaml` 向 DAM 声明能力面，DAM 把它登记为 Deployed Instance 并双向通话。

```text
┌─────────────── ai-native-dam（治理平面，唯一事实源）────────────────┐
│  mcp-gateway：唯一 /mcp · approval_requests · rights_records        │
│  部署注册：register_deployment_target / register_deployed_instance  │
└──────────────▲───────────────────────────────┬─────────────────────┘
               │ unit → DAM                    │ DAM → unit
               │ check_use / record_usage /    │ probe /healthz
               │ register_skill（走 DAM 工具）  │ push version / revoke
┌──────────────┴───────────────────────────────▼─────────────────────┐
│  Video Batch ID（InstallableUnit L2）                                │
│  dam.manifest.yaml ←── 本方案的交付物                                │
│  15 个 MCP 工具 · 两段式审批（-32042）· A2A 只读委派 · 本地 SQLite   │
└─────────────────────────────────────────────────────────────────────┘
```

**这条路线砍掉了 v1 的大头**：

| v1 计划项 | v2 处置 |
|---|---|
| PR-1 五包 ESM 化 + vitest 改写 + Zod 换装（3-4 人日） | **不需要**——单元保留自有工具链，L1/L2 契约不规定内部实现 |
| PR-2 gateway tools.ts registry 重构 + 工具收编（4-5 人日） | **不需要**——工具留在单元自己的 /mcp，DAM 通过 manifest 发现 |
| 表名对齐迁移（rights_records/approval_requests 等） | **推迟**——仅当数据边界将来上移 DAM Postgres 时才需要 |
| PR-0/PR-3/PR-4 | 折叠为下方「剩余步骤」 |

### 步骤 2 · unit → DAM 接线（1-2 人日，本仓库）

按 ADR 0009 §3 双向通话的方向性，本单元对 DAM 的三类调用改走 DAM gateway（env `VBID_DAM_BASE_URL` + Bearer）：

| 单元内工具 | 接线后行为 |
|---|---|
| `check_use` | 代理到 DAM `check_usage_rights`（rights_records 唯一事实源）；DAM 不可达时降级本地 rights 表并标记 stale |
| `record_usage` | 双写：本地 audit + DAM `record_usage`（usage_records） |
| `register_skill` | 门槛裁决（≥3 任务/≥8 变体/👍率≥60%）保留在单元侧，通过后调 DAM `register_skill` 进 Registry |

本地 SQLite 8 表**保留**——它们是单元执行状态（dataBoundary 已声明），不是治理状态。

### 步骤 3 · Streamable HTTP 完整化（1 人日，本仓库，可并行）

manifest 已诚实声明 `transport: jsonrpc-http`（plain POST，无 SSE）。补齐 MCP Streamable HTTP 的 SSE/会话恢复后改声明。不影响安装——DAM 探针只用 `/healthz` + JSON-RPC。

### 步骤 4 · Skill 入境闭环（持续）

真实素材到位 → 跑任务过门槛 → `register_skill` → 更新 manifest `skills:` 列表 → DAM 侧 upgrade install 批量登记（ADR 0009 §4「标准入境程序」）。

## 五、风险与红线（不因路线变轻而放松）

- **审批红线**：`submit_generation` 两段式人工确认永不自动批——unit 被 DAM 托管、被 A2A 委派都不改变这一点
- **Skill 直跑即违规**：单元只能经 gateway `apply_skill` 触发 Skill，越权执行吊销 install 批准（ADR 0009 §4）
- **manifest 与契约同步**：`dam.manifest.yaml` 的 tools 表必须与 `MCP_TOOLS` 一致——建议把 v2 提交里的对拍脚本固化成 CI 检查（后续任务）
