## 二、现状核查结果（真实差异，不是猜测）

### 2.1 数据表：命名并未完全对齐（docs/06 的乐观假设需修正）

| VBID SQLite（8 表） | DAM Postgres（0001/0002 迁移） | 处置 |
|---|---|---|
| `assets` | `assets` ✅ | 平移，列对齐核查 |
| `tasks` | **无对应表** | 新增 `distiller_tasks`（DAM 新迁移，见 PR-0） |
| `rights` | `rights_records` ⚠️ 命名不同 | rename 平移 |
| `approvals` | `approval_requests` ⚠️ 命名不同 | rename 平移 |
| `audit_log` | **无独立表**（审计由 `approval_requests` + `usage_records` 承载）⚠️ | 裁决 A：VBID 审计事件并入 DAM 审计载体，或新增 `audit_events` |
| `knowledge_entries` | `knowledge_entries` ✅ | 平移 |
| `skills` + `skill_versions` | `skills`（version 行内列，`UNIQUE(id, version)`）⚠️ 两表合一 | 合并平移 |
| `tasks` 产物变体（`assets.parent_id/task_id`） | `assets` 已有 provenance 字段族 | 平移 |

### 2.2 工具面：15 个里 6 个与 DAM 已有工具**语义重复**

| VBID 工具 | DAM mcp-gateway 对应 | 处置 |
|---|---|---|
| `search_assets` | `SearchAssets` ✅ 已有 | **退役** → 调 DAM 原生 |
| `check_use` | `CheckUsageRights` ✅ 已有 | **退役** → 调 DAM 原生 |
| `record_usage` | `RecordUsage` ✅ 已有 | **退役** → 调 DAM 原生 |
| `write_knowledge` | `WriteKnowledge` ✅ 已有 | **退役** → 调 DAM 原生 |
| `search_knowledge` | `SearchKnowledge` ✅ 已有 | **退役** → 调 DAM 原生 |
| `register_skill` | `RegisterSkill` ✅ 已有（但 DAM 无 VBID 的门槛裁决：≥3 任务/≥8 变体/👍率≥60%） | 退役工具本体，**门槛裁决逻辑移植进 DAM RegisterSkill 前哨**（作为 domain 校验钩子） |
| `parse_master` / `suggest_matrix` / `get_analysis` / `get_lineage` / `create_task` / `review_variant` / `submit_generation` / `list_tasks` / `list_skills` | 无 | **保留**，以 video-distiller 工具提供方并入 gateway |

净结果：**DAM 工具面 30+ → 约 35**，新增 9 个视频域工具，重复 6 个收编。

### 2.3 工程链差异（必须排期的改造，不是零改动）

| | VBID | DAM | 迁移动作 |
|---|---|---|---|
| 模块系统 | CJS 倾向 / node 原生跑 `.ts` | ESM + `tsc -b` 出 `dist/` | video-distiller 改 ESM + 进 tsc 构建 |
| 测试 | `node --test`（19 个测试文件） | `vitest` | 测试改写 vitest（机械工作，~2 天） |
| Schema | 手写校验器 207 行 | Zod（`@ai-native-dam/shared-schema`） | VBID shared-schema **整体退役**，调用点换 Zod 版 |
| 数据库 | `node:sqlite` 同步 API | Postgres（`pg` 异步，gateway 已有 pg-store 全套范式） | 数据层重写走 pg，照抄 `pg-approval-store.ts` 等范式 |
| 服务端 | 自建 `node:http` 路由 ~1000 行（/mcp + REST + A2A + 静态托管） | mcp-gateway（Cloudflare Workers，`packages/mcp-gateway/src/worker.ts`） | **这是最大的一块**：VBID apps/api 逻辑按平面拆开，分别进 gateway / 退役 |

**代码量**：VBID 全仓 TS 约 6,000 行（packages ~2,000 + apps ~4,000），其中 apps/api 的 server/mcp/db 约 3,500 行需要按平面拆分处置，不是整体搬运。

### 2.4 已确认的契合点（好消息）

- `knowledge_entries` 表名/分层（raw/topic/rule/manual/qa）完全一致 ✅
- 治理语义（risk-levels / approval-gates / permission-scopes 三份 yml）VBID 已照抄 DAM 格式 ✅
- SPA 已是纯 MCP 客户端（读写全走 `/mcp`），迁后端无需改前端 ✅
- 两段式审批（`-32042` + token）与 DAM `approval_requests` 语义同构，gateway 已有 `approval.ts` ✅
- e2e 验证脚本（`scripts/e2e-synth.cjs`）与 A2A 断言（`scripts/a2a-verify.mjs`）可直接改造为 DAM 侧验收测试 ✅

## 四、PR 切分（5 个 PR，每个独立可合并、测试全绿）

> 原则：docs/06「对齐即迁移」——每个 PR 合并后 DAM 都还是可发布状态；VBID 仓库在每个 PR 后照常能跑。

### PR-0（DAM）· `feat(distiller): 数据基座迁移 0003`

- `infra/migrations/0003_video_distiller.sql`：`distiller_tasks`（视频生成任务，含 matrix_json/variant_count/tier/成本列）、`audit_events`（裁决 A 选①时）、VBID→DAM 列对齐所需的 `assets` ALTER（provenance/谱系列核查后补齐）
- `infra/seed/`：档位预设（economy/standard）种子数据
- 纯 SQL + 回滚 SQL，零代码。**验收**：`psql` 应用/回滚各一次干净通过

### PR-1（DAM）· `feat(video-distiller): 执行平面五包并入`

- 新建 `packages/video-distiller/`：variable-matrix / reference-parser / gen-provider / media-probe / pipeline（自 VBID 原样搬入）
- 工程化改造：ESM 化、进 `tsconfig.base.json` 构建、19 个 `node --test` 测试改写 vitest、shared-schema 调用点换 `@ai-native-dam/shared-schema` Zod 版
- **明确不做**：不碰 gateway、不碰治理、不带 apps/api
- **验收**：`pnpm --filter @ai-native-dam/video-distiller test` 全绿（测试用例与 VBID 侧逐一对应，数量不减）

### PR-2（DAM）· `feat(video-distiller): 视频域 MCP 工具注册进 gateway`

- mcp-gateway 增加工具提供方接口（小重构：`tools.ts` 1215 行抽出 registry，video-distiller 注册 9 个新工具）
- 6 个重复工具在 VBID 客户端侧改指 DAM 原生（SPA 的 `mcpTool` 桥换工具名，前端小改）
- 门槛裁决（裁决 B 选①时）进 DAM RegisterSkill 前哨
- `submit_generation` 的两段式审批接 DAM `approval_requests`（替换 VBID 本地令牌表，语义已同构）
- **验收**：① `scripts/e2e-synth.cjs` 改造版对 DAM gateway 全绿（摄入→审批→真实生成→产物，economy ~$0.12）② 全新 MCP 客户端（Claude Desktop）完成「选素材→二创→审核」链路（docs/06 P2 验收标准）

### PR-3（DAM）· `feat(distiller): A2A 委派 + 谱系/审核工具补齐`

- `/.well-known/agent.json`（Agent Card）+ `POST /a2a/message/send` 只读委派（gated draft 提案，**绝不自动执行**——红线随迁移保留）
- `get_lineage` / `review_variant` / `list_tasks` / `list_skills` 若 PR-2 未全量做，在此补齐
- **验收**：`scripts/a2a-verify.mjs` 移植版 13/13 PASS（含零副作用断言）

### PR-4（VBID→DAM）· `chore: 数据迁移 + VBID 归档`

- SQLite→Postgres 迁移脚本（8 表 → DAM 表族；12 条 file_path 失效的 Master 记录**不迁**，只迁有效数据与知识/Skill 资产）
- VBID 仓库：README 加托管指引 + 仓库归档只读；SPA 按裁决 C 处理
- **验收**：迁移脚本干跑（dry-run）对账：资产数/知识条数/Skill 数两边一致
